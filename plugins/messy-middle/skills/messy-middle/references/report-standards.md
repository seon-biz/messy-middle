# 진단 리포트 · 개선 기획서 표준

두 문서 모두 마크다운 실무 문서다. 슬라이드를 만들지 않는다. 판정 근거를 숨기지 않고 문서 상단에 명시한다.

## 진단 리포트 (평가 모드)

대상: 상세페이지·웹페이지·블로그 글·광고 카피·(범위가 '전체'면) 채널 구조.

### 구조
1. **판정 요약** — 분기표 5축 + 진단 범위 축 판정. 미확인 항목은 "추정" 표기.
2. **6편향 스코어카드** — ◐ 부분활용 / ○ 활용 / ✕ 미활용 + 각 한 줄 진단 + 우선순위.
3. **모드 적합성 진단** — 대상 콘텐츠가 탐색용인지 평가용인지, 편향이 단계에 맞게 쓰였는지. 특히 희소성·즉각성은 **사실 기반 여부를 먼저 구분**한다: 제철·실재고·실제 정책 기반 한정은 자산(유지·강화), 인위적 기한·압박만 위치 오류·제거 대상.
4. **링크 동선 점검** — 2단 링크 기준(knowledge.md §4-3): 탐색 콘텐츠가 사이트로 직행하는가, 평가 허브로 모이는가.
5. **상세페이지 점검** (해당 시) — knowledge.md §4-6 ⑤ 블록 골격 기준: 권위가 상단인가, 불안마다 숫자 블록이 있는가, 즉각성이 하단 한정인가.
6. **콘텐츠 허브 점검** (해당 시) — §4-6 ②-2 기준: 첫 문단 직답, 이름 붙인 1차 데이터, 방문 장치(도구·자료), CTA 글당 1개, 제목 연도·갱신.
7. **우선순위 수정 목록** — 가장 큰 결함부터, 각 항목은 행동 문장으로.

### 범위별 조정
- 카테고리: 대표 상품 2~3개를 표본으로 점검하고 공통 결함과 개별 결함을 나눈다.
- 사업 전체: 3~7항 대신 고객 여정 지도(트리거→탐색⇄평가→구매에 실제 키워드·채널 배치)와 "비어 있는 구간" 진단을 중심에 둔다.

## 개선 기획서 (기획 모드)

보통 진단 리포트에 이어 작성한다. 구조:

1. **판정 요약 + 스코어카드** (진단과 동일 형식, 갱신분만)
2. **한 문장 전략** — 입말 선언 1줄.
3. **수정 항목 × 채널·모드 매핑** — knowledge.md §4, §4-6 플레이북 기준. 2단 링크 + 탐색 압도적 다수를 기본 동선으로.
4. **채널별 실행** — 포맷 수준까지: 유튜브 3폼+링크 동선, 블로그 정보형/비교검증형, 인스타 4포맷, 상세페이지 블록, 커뮤니티/메신저. 각 콘텐츠에 발행 가능한 제목·소재 예시를 반드시 단다 (탐색 글 제목 5개 이상, 평가 허브 1편 상세).
5. **도구 제안** (해당 시) — 이름은 "[고객의 공간/상황]+[얻는 결과]" 한국어 구조(기능어 금지), 고객 여정 4단계 흐름, 실존 벤치마크 1~2개 웹 검색 확인 + 차별점, 문의 데이터 없으면 "가설" 플래그. 다품종·복잡 규격은 파인더 유형 우선.
6. **발행 후 루틴** — 분기 갱신+제목 연도, 월 1회 AI 직접 검색으로 인용 확인, UTM으로 "이름 알린 글"/"구매 만든 글" 분리, 잘 되는 허브로 링크 몰아주기.
7. **실행 로드맵** — 단계 카드: 하는 일(행동 문장) + 왜 이 순서 + 이번 주 첫 행동. 불안이 가설이면 맨 앞에 "문의·후기부터 모은다 → 불안 재확인" 배치.

기획서는 실무 문서이므로 편향 용어를 써도 되지만, 고객에게 노출될 문구(제목·카피 시안)에는 번역투 금지 패턴(deck-standards.md의 9종)을 적용한다.

## 납품 전 점검 (두 문서 공통)

- [ ] 판정 요약·스코어카드가 상단에 있는가
- [ ] 희소성을 사실 기반/인위적으로 구분했는가
- [ ] `[운영]` 지식을 구글 연구로 귀속하지 않았는가
- [ ] 수치가 knowledge.md §3 표기와 일치하는가
- [ ] 추정·가설 항목에 플래그가 있는가
- [ ] 수정 목록·로드맵이 행동 문장인가
- [ ] 고객 노출 문구를 소리 내어 읽어 번역투가 없는가
- [ ] 문서 맨 끝에 제작 표시 한 줄이 있는가 (그 외 위치에는 없음)
