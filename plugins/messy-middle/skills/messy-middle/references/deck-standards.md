# 전략 덱 표준

덱 작업은 2단계다: ① 슬라이드 스펙(md) 완성 → ② design-template.md 기준으로 Reveal.js 단일 HTML 빌드. 스펙 없이 바로 HTML을 만들지 않는다. 두 파일 모두 저장한다.

## 전체 구조 (총 19~34장)

| 부 | 챕터 | 장수 |
|---|---|---|
| 도입 | 표지 · 루프 · 근거 수치 | 3 고정 |
| 실전부 | 진단 | 3–5 |
| 실전부 | 전략 | 2 |
| 실전부 | 상세페이지 | 2–3 |
| 실전부 | 채널 실행 (발행 세트 5장 포함 가능) | 6–14 |
| 실전부 | 광고 | 1–4 |
| 실전부 | 마무리 | 2–3 |

이론 교육 챕터는 없다. 개념은 도입 루프 슬라이드(화면)와 각 슬라이드의 설명(최초 등장 시 한 줄 풀이)으로만 가르친다.

## 도입 3장 표준

1. **표지** — 제목 고정 "복잡한 구매 여정, 메시미들" / 부제 "메시미들(Messy Middle) 마케팅 전략" / 클라이언트명·날짜 / "Google × The Behavioural Architects 「Decoding Decisions」 기반".
2. **루프** — 제목 "고객은 사기 전에 빙빙 돈다". 중앙 루프 다이어그램(트리거 → 탐색⇄평가 반복 → 구매), 화면 풀이: 탐색="이것저것 둘러보는 중" / 평가="살까 말까 따져보는 중". 하단: "둘러보는 고객과 따져보는 고객에게는 다른 말을 걸어야 한다." 퍼널 유효성은 설명에 1~2문장. 깔때기 비교 화면 금지.
3. **근거 수치** — 카드 3장, 각각 "실험 상황 → 큰 숫자 → 결과" 3줄 스토리: 30~40%(보여주기만), 2배(정돈만 — 반드시 포함), 28~87%(신호 전부). 하단: "새로 만들기 전에, 보여주고 얹으면 이긴다."

## 실전부 챕터 규칙 (요지)

- **진단**: 고객의 언어로 시작. ① 결제 직전 멈추는 이유 카드(실제 인용 1줄 + 불안 이름 — 데이터 없으면 추정 명시) ② 고객 여정 지도(필수 — 실제 키워드·채널을 루프에 채움) ③ 불안↔보유 자산 짝짓기("새로 만들 것이 아니라 꺼낼 것") ④ 채널 현황(선택, 데이터 있을 때만). 판정표·스코어카드·희소성 판정을 슬라이드로 출력하면 실패.
- **전략**: 입말 선언 1줄 크게 + 행동 언어 우선순위 목록. 편향 용어를 화면에 쓰지 않는다.
- **상세페이지**: 독립 챕터 필수. 실물 페이지 기준 "멈추는 지점 → 이 순서로 고친다(각 항목에 답하는 불안 짝지음) → 전/후(선택)". 페이지 미확인이면 신규 설계 제안 + 확인 필요 명시. 블록 골격 표 자체는 화면에 내보내지 않는다.
- **채널**: 채널 지도(깔때기: 탐색 여러 편 → 평가 허브 하나 → 사이트) → 블로그 탐색/평가 → 유튜브 쇼츠·미들폼/롱폼 → 인스타 4포맷 → 기타. 모든 채널 슬라이드에 실제 발행 가능한 예시 필수(탐색 제목 5개+, 허브 1편 상세). 원칙 나열만 있는 슬라이드는 실패. 탐색 구간에 희소성·즉각성·압박 금지(사실 기반 한정도 평가 구간에만).
- **발행 세트** (검색·AI 발견이 중요하거나 1차 데이터 보유 시, 5장 각각 별도): 두 가지 일 / 글의 뼈대(실물 예시) / 도구 제안(report-standards.md의 도구 표준과 동일) / AI 추천 만들기(이름 붙이기 + 남이 말해주게; 조작 금지) / 발행 후 점검 표.
- **광고**: 본격 집행이면 탐색/평가 분리 카피 2–4장, 미집행·소액·미확인이면 원칙 변형 1–2장("지금 안 해도 됩니다 → 시작한다면 2종 소액 테스트 → 틀기 전에 도착 페이지부터"). 챕터 생략 금지.
- **마무리**: 로드맵 카드(하는 일 + 왜 이 순서 + **이번 주 첫 행동**) + 측정 표("보는 숫자 / 이 숫자가 오르면 무슨 뜻"). 불안이 가설이면 로드맵 맨 앞에 재진단 순서.

## 문장 원칙 (하드 룰)

**번역투 금지 9종:** ① 추상명사+"만든다/유발한다"(→ 고객의 행동 장면으로) ② 조사 생략 명사구 압축(→ 주어·서술어 갖춘 문장) ③ 정의 없는 개념어 ④ 영어 관용구 직역 ⑤ "~를 통해" 남용(→ "~로") ⑥ 피동형 남발("형성된다"→"고객이 마음을 정한다") ⑦ 한자어 명사화("표면화"→"꺼내 보여준다") ⑧ "~하는 것이 중요하다"(→ "~부터 한다") ⑨ "~에 대한" 남용.

- 슬라이드 제목은 "시키는 일" 또는 "답하는 질문"의 문장. 내부 용어·플래그를 제목에 쓰지 않는다.
- 모든 슬라이드는 화면만 읽어도 이해되어야 한다. 검증: 이 슬라이드만 캡처해 보내도 실행할 수 있는가.
- 질문 블록 금지. 확인 항목은 설명에 평서문으로.
- **낭독 점검(납품 전 의무)**: 제목 전수와 핵심 문장을 소리 내어 읽는 것을 상정해 9종 표와 대조하고, 걸리면 고친 뒤 출력한다.

## 용어 표준 (화면·다이어그램 한글 고정)

노출 배경(Exposure) · 트리거 · 탐색/평가 · 깔때기(퍼널, 설명에서만) · 대표 지표 판단 · 소셜 프루프 · 쇼잉업(Showing Up, 최초 언급 시 "눈도장 찍는 일" 풀이) · 끌리게 만들기(Supercharging) · 구매. 원어 병기는 최초 등장 1회만.

## 슬라이드 스펙 형식

```
## 슬라이드 N — [챕터] [제목]

**시각 콘텐츠**
- 레이아웃: [표 / 카드 / 타임라인 / 다이어그램 / 선언 등 — design-template.md의 유형명 사용]
- [화면 요소]

**설명**
[설득 논리. 확인 필요 항목은 문장으로 포함.]
```

스펙 맨 위에 매니페스트(챕터별 장수 표)를 붙인다.
