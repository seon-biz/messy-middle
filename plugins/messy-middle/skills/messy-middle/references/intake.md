# 인테이크 라우팅 — 경우별 질문 세트

라우팅 3문항의 답으로 아래 6경우 중 하나를 고르고, 그 경우의 **필수 질문만** 묻는다. 선택 항목은 그 뒤에 한 번에 제시한다. 사용자가 준 자료(URL·파일·설명)에서 이미 답을 알 수 있는 질문은 묻지 않고 채운 뒤 "확인했습니다"로 알린다.

## 진단 범위 축 (분기표 5축에 추가되는 여섯 번째 축)

| 범위 | 산출물이 달라지는 지점 |
|---|---|
| 개별 (상품/서비스 하나) | 상세페이지·리뷰 중심 진단. 표준 워크플로 그대로 |
| 카테고리 (상품군·라인업) | 대표 상품 2~3개 선정 + 공통 불안 진단. 허브 콘텐츠는 카테고리 허브. 여러 상품 중 고르게 돕는 파인더형 도구 우선 검토 |
| 사업 전체 (가게·브랜드) | 고객 여정 지도·채널 구조 진단이 중심. 상세페이지는 대표 사례 1개로만 |

**역제안 규칙**: 상품 수가 많고(대략 10종 이상) 규격·용도가 갈리는데 개별 진단을 요청하면, "상품군 전체로 보는 것이 더 맞아 보입니다 — [이유 한 줄]"로 한 번 제안한다. 사용자가 개별을 고수하면 따른다.

## 경우별 필수 질문

### A. 상품 × 개별
1. 상품 판매 페이지 주소 (없으면 어디서 파는지)
2. 리뷰·후기가 몇 건쯤 있고, 어디에 있는지
3. 대략의 가격대와, 고객이 사기 전 가장 망설이는 점 (아는 만큼만)

### B. 상품 × 카테고리
1. 상품군의 구성 — 몇 종류이고, 무엇으로 나뉘는지 (사이즈/용도/맛 등)
2. 가장 잘 팔리는 상품 1~2개와 그 판매 페이지 주소
3. 고객이 "뭘 골라야 할지" 물어보는 일이 잦은지

### C. 상품 × 사업 전체
1. 파는 채널 전부 (자사몰/쿠팡/스마트스토어/오프라인 등)
2. 첫 구매 고객이 주로 어디서 오는지 (아는 만큼만)
3. 대표 상품 1개의 판매 페이지 주소

### D. 서비스 × 개별
1. 서비스 소개 페이지 주소 (없으면 어떻게 안내하는지)
2. 고객 후기·사례가 있는지, 공개 가능한지
3. 무료 상담·체험·샘플 같은 첫 경험 장치가 있는지

### E. 서비스 × 카테고리 (여러 서비스 상품)
1. 서비스 구성 — 몇 가지이고 무엇으로 나뉘는지 (등급/대상/기간 등)
2. 가장 많이 팔리는 서비스와 그 안내 페이지
3. 고객이 상담에서 가장 자주 묻는 질문 1~2개

### F. 서비스 × 사업 전체
1. 고객이 오는 경로 전부 (검색/소개/광고/플랫폼 등)
2. 상담·문의에서 가장 자주 나오는 질문이나 걱정
3. 사업 소개를 볼 수 있는 곳 (사이트/블로그/인스타 아무거나)

## 공통 선택 항목 (모든 경우, 한 번에 제시)

```
비워두셔도 됩니다 — 제가 추정하고 "추정"으로 표시합니다.
- 타깃 고객:
- 현재 운영 채널: (블로그/유튜브/인스타/기타)
- 광고 집행 여부: (본격 / 소액·간헐 / 안 함)
- 영업 권역: (지역명 / 전국)
- 권위 자산: (경력/인증/수상/언론 등)
- 직접 확보한 숫자: (판매 건수/실측/기간 등)
- 고객 문의·FAQ 기록 유무:
```

## 판정 연결

- 필수 질문 답 → 분기표 ①(물리/무형) ②(무료 대체재) ⑤(관여도)와 6편향 스코어카드의 1차 근거.
- 선택 항목 → ③(광고) ④(권역)과 채널·콘텐츠 설계 근거.
- 빈 항목은 카테고리 기준으로 추정하고 산출물에 "추정 — 확인 필요"를 명시한다. 리뷰·FAQ 데이터가 없으면 고객 불안은 가설로 취급하고, 로드맵 맨 앞에 "문의·후기부터 모은다 → 불안을 다시 확인한다"를 배치한다.
